# reports/

Public drift reports — model-version-bound measurements of how agent skills hold
up as the substrate underneath them changes — plus the QA records behind them.
The rendered versions live at [driftproofhq.com](https://driftproofhq.com); every
report is re-derived from the receipts under [`../receipts/`](../receipts/).

The three report types share one band-based, floor-gated verdict rule and differ
only in what moves underneath the skill — see
[`../REPORT-STYLE.md`](../REPORT-STYLE.md) for the shared chrome and
[the methodology page](https://driftproofhq.com/methodology.html) for the rule.

## Also here

- **`example-drift.md`** — a worked drift report between two receipts of the
  example skill (`examples/commit-message-conventions`), generated by
  `driftproof diff`. It demonstrates the band-overlap verdict logic on real data.
- **`example-receipts/`** — the sampled receipts that worked example is built
  from, kept as reference artifacts you can re-validate with `driftproof validate`.
- **`report-00N-qa.md` / `report-00N-run.log`** — pre-publish QA records and run
  logs for each report, kept so the published numbers stay auditable.
- **`rubric-sweep.md`**, **`report-001-audit.md`** — methodology hardening
  records from Report #001.
- **`pending-publish.md`** — the queue where the model-release trigger
  (`scripts/release-watch.js`) parks auto-drafted reports awaiting human review.
  Unreviewed drafts never ride a publish, so this queue stays out of the
  published tree.

Each published report is reproducible: it names the exact model, skill
`content_hash`, suite `suite_hash`, and judge settings, and links the receipts it
was computed from.
