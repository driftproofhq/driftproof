Glossary

Twenty-five words this site uses in a particular way. Each entry opens in plain words, then gives the fuller meaning, and links to the section it comes from. The verdict rule, in the methodology's own words: Where bands touch or overlap, or a move is below the floor, the report says no separation detected at this sample size: never drift, and never that nothing changed.

Skill

A file of instructions that people add to an AI assistant, such as Claude, to make it better at a job. Driftproof tests whether a skill really helps.

A directory holding a SKILL.md, whose instructions are sent with every request in the with-skill arm and are measured by their content hash, so a receipt names the exact bytes it read. The skill's own test cases are the tasks a run asks. Source: with and without the skill.

Drift report

A report that asks whether a skill still helps after something underneath it changed, such as a new version of the model.

A dated comparison of two runs of the same eval suite, asking whether a skill still helps after something underneath it moved. It names what moved, reports a verdict per cell, and links the receipts every figure came from. Source: the drift verdict rule.

Receipt

The dated file that records one test: the skill, the model, every score and the result. Anyone can check that it has not changed since it was sealed.

The dated, hash-verified JSON file a single run emits: the skill and its content hash, the model, the surface, every case score, and the comparison between the two arms. It is the unit of evidence on this site, and every published number traces to one. Source: the receipt specification.

Band

The range a score is given instead of one number: the average plus or minus the usual spread of the scores. Two bands that do not overlap are what a report calls separated.

The range a score carries instead of a single number, because a scorer asked twice does not answer identically twice. A band is a descriptive spread, the mean plus or minus one sample standard deviation across n generations scored by the fixed judge, and whether two bands overlap decides whether a separation is detected under the rule. Source: with vs without, sampled, banded.

Draw

One answer the model gave to a task. Each task is asked several times, so a result is a range of scores rather than one number.

Each arm is generated several times, and more until the spread across draws settles. The judge scores every draw several times, and a receipt records how many draws each arm had. Source: where a band comes from.

Separated

The two ranges of scores, with the skill and without it, do not overlap, and the gap is at least the effect floor. It is what a report means by a clear difference, and it is not proof that the skill caused it.

Separation is detected under the rule when the two bands do not overlap and the move clears the effect floor; it is a detection under the rule, not proof that the skill moved the score. Where bands touch or overlap, or a move is below the floor, the report says no separation detected at this sample size. Source: the drift verdict rule.

Effect floor

The smallest gap that counts. A smaller difference is not called a change, however the ranges fall, because the grader scores in coarse steps.

The smallest lift that counts as a lift, below which a difference is reported as no effect however the bands fall. It exists because a score can move by a rounding artefact of the scoring grid and mean nothing at all. Source: the drift verdict rule.

Baseline

The run without the skill: the same tasks and the same model, with nothing added. Every score with the skill is compared against it.

The arm run without the skill text, against which the with-skill arm is read: the lift is the with-skill mean minus the baseline mean. A placebo arm, where a report has one, is read against the baseline too. Source: with and without the skill.

Placebo arm

A fake skill: a text of the same length as the skill, built from sentences chosen without looking at any task. The skill is scored against the fake as well as against nothing, the way a medicine is tested against a sugar pill.

An optional third arm, answered with a text of exactly the skill text's length in bytes in the skill's place, drawn from a fixed corpus chosen without reference to any task, which can by chance bear on a case. Its reading is the verdict's own case rule applied to the skill against that text, given beside the verdict and never in its place. Source: the receipt specification.

Judge

The judge, also called the grader, is an AI model, sometimes the same one that answered, that scores each answer against a guide written for the task. It is an AI, not a person, and it can be wrong.

One fixed grader scores every answer in a report several times, so a moved result cannot come from a changed grader; the judge's model, instructions and sampling are recorded on the receipt. The judge policy says when the grader changes and what it cannot do. Source: why one grader.

Case rule

A reading that takes each test task on its own. A skill clearly helped if it scored clearly higher on at least one task and clearly lower on none, and clearly hurt if it scored clearly lower on any.

The rule reads each case's two bands under the effect floor and combines the cases: separated upward on at least one case and downward on none reads as helped, and downward on any case reads as hurt. The aggregate figures over all cases are given beside it and can point the other way. Source: repeat, then read the case rule.

Substrate

The model underneath the skill, down to its exact version and the company that serves it. Skills stand still while the model underneath them moves.

The model underneath the skill: a specific version, from a specific provider, at a specific tier. Driftproof exists because the substrate moves while the skill file stands still. Source: providers, surfaces and neutrality.

Surface

How the model was reached: through a paid programming interface or through a subscription command-line tool. The same model can behave a little differently over the two.

How the model was reached: a metered API or a subscription CLI. The same model over two surfaces is not guaranteed to behave identically, so every receipt records which one it ran on. Source: providers, surfaces and neutrality.

Refusal

A result that reports no verdict because the run could not stand behind one. It is published as a refusal rather than guessed at.

A published result that reports no verdict, because the run could not stand behind one. A refusal is an outcome and not an error, and publishing it is the alternative to guessing. Source: the drift verdict rule.

Cell

One skill tested on one model. A report is a grid of cells, and each cell gets its own verdict.

One skill measured on one substrate: the smallest unit a report gives a verdict to. A report is a grid of cells, and a cell that refuses does not sink the ones that did not. Source: with vs without, sampled, banded.

Arm

One side of the comparison: the run with the skill, or the run without it. Some reports add a third arm, the fake.

One side of the comparison: the run WITH the skill, or the baseline run without it. Every case is run in both arms, and the difference between the two arms is the only thing a lift can mean. Source: with vs without, sampled, banded.

Lattice

The four levels of trust a receipt can carry, from a number nobody checked, through one Driftproof measured itself, to one checked by a formal proof.

The four verification levels a receipt can carry: UNVERIFIED, DECLARED, TESTED and FORMAL. A number Driftproof measured itself is TESTED; a number imported from another tool is DECLARED, recorded but not verified, and never given a pass or fail verdict. Source: receipts are an open format.

Generation sampling

Asking the model the same task several times, so the range measures the model giving different answers and not only the grader re-reading one answer.

Running each arm more than once, so that a band measures the model writing a different answer and not only the judge re-reading one. A receipt that ran no generation sampling carries a legacy band, and one that ran it carries a generation band. Source: where a band comes from.

Band source (legacy, generation)

A label beside a range saying how it was measured: from one answer scored several times, or from several answers each scored several times.

The label a report table puts beside a band, saying which instrument produced it. A legacy band is the judge re-scoring a single generation; a generation band is the across-draw spread of several. Source: where a band comes from.

Context file

A file of standing instructions, such as a CLAUDE.md or an AGENTS.md, tested in place of a skill.

Any Markdown file, such as a CLAUDE.md, an AGENTS.md or a shared rules file, measured as a subject in place of a skill. Its exact bytes are the with-skill system text and their sha256 is its content hash; the receipt records its kind as context_file. Source: the receipt specification.

Delivery

How the skill's text reached the model in a run: put into each request by Driftproof, loaded by a tool that had it installed, or not recorded.

How a run was configured to deliver its subject, recorded on every receipt: injected, the runner puts the subject text into each with-skill request it builds; installed, a harness loaded the subject from where it was installed, which only an import says; unknown, an imported source that does not say. It records the configuration, not that a request was sent. Source: the receipt specification.

Router

A skill that hands the job to another skill or tool instead of doing it itself. The text tasks here can only test what a router writes back, not the work it hands off, so a router gets no verdict.

A skill whose instructions delegate the task to another skill or tool, so a text-only run tests its written response and not the delegated work. Report 015 Amendment 1 records the limit: a router's receipt gives no verdict, because the skill it hands off to was not tested, and its rows are left out of the headline counts. Source: Report 015 Amendment 1.

Repository capture

A way of testing where the model works inside a fresh copy of a code repository, with its tools, and the changes it makes are graded along with its reply.

A capture mode that grades the reply and captured text changes from a fresh pinned starter repository, with coding tools available. The receipt discloses observed tool evidence and capture omissions; availability alone does not prove execution. Source: repository capture.

Checkpoint

Saved progress of a run, so a paused or interrupted run can continue without redoing finished work.

Durable run progress that retains finished draws and saved judge samples for a compatible resume. A pause or resume leaves the verdict rules unchanged and records the run segments in the final receipt. Source: checkpoint, pause and resume.

Crossed judging

An older grading setup in which two models graded each other's answers. One grader now scores both.

A historical R-2 pairing: Sonnet judged Haiku and Haiku judged Sonnet. Sonnet 5.5 now judges both targets; self-grading is disclosed. Source: R-2 judge configuration.
